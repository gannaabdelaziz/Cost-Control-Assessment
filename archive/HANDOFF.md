## Combined portal — build & answer enhancement

The live site is the repo-root `index.html`, **generated** by
`work/build_combined_assessment_app.mjs`. Never hand-edit the root `index.html`; edit the
sources/build script and rebuild.

**Rebuild (from the `archive/` folder):**

```powershell
node work/build_combined_assessment_app.mjs
```

This regenerates both `publish/index.html` (build artifact) and the repo-root `index.html`
(live site). A clean run prints `Built ... with 5 departments and 300 questions.` The build
throws if any department ≠ 60 questions, domain weights ≠ 100, or an answer set is malformed —
so a successful build is also the content-integrity check.

### Enhancing the maturity answers (the 5 level descriptions per question)

By default each question's five answer descriptions are auto-generated by `answerAnchors()`
(generic, keyword-matched templates). To replace them with specific wording, add a per-question
override in the `questionRewrites` object of the build script:

```js
questionRewrites = {
  "document-control": {
    "Receipt Ownership": {
      answers: [
        "Level 1 description …",
        "Level 2 description …",
        "Level 3 description …",
        "Level 4 description …",
        "Level 5 description …"
      ]
    }
  }
}
```

Rules:
- Key each override by the question's **`category`** (the short control name).
- `answers` must be **exactly 5 non-empty strings** (build enforces this).
- Any question left out keeps the generic `answerAnchors()` template — you can enhance
  incrementally, one category at a time.
- The same entry can also override `text`, `evidence`, `theme`, `impact`, etc. (see the
  Cost Control block for examples).

Empty scaffolds already exist for `document-control`, `planning-controlling`,
`project-procurement`, and `technical-office` — just fill them in and rebuild.
