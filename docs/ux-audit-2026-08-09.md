# UI/UX Audit — Madkour Department Assessment Portal

**Date:** 2026-08-09
**Scope:** `index.html` (portal home + assessment app, all views)
**Method:** Live browser interaction at 1440 / 1200 / 1024 / 768 / 390px. Contrast
ratios computed from rendered pixels with gradient-aware background compositing.
Focus order tested with real `Tab` presses. Destructive paths traced in source.
**Status:** Diagnosis only — no code changed.

---

## Summary

1. **Restore silently destroys all five departments' answers with no confirmation.**
   `restoreAll` writes straight to localStorage, while the far less damaging
   "Reset Current Department" *does* confirm. Worst finding in the app.
2. **`saveSilent()` has no try/catch.** In Safari private mode or on quota
   exceeded, every answer click throws and nothing saves, with zero user feedback.
   Silent data loss on a 300-question instrument.
3. **Horizontal page scroll between 901px and 1199px.** The Portfolio Overview bar
   needs 698px but gets 559px and nothing in it can shrink; the arrow lands at
   x=1067 in a 1024 viewport. Covers the whole small-laptop / iPad-landscape range.
4. **Amber accent fails AA at 3.19:1** — `#d97706` on white, on both the "04" badge
   and the "Open assessment →" link of the Project Procurement card.
5. **No `aria-live` anywhere (0 regions).** Selecting an answer silently changes
   completion %, maturity and score. Screen-reader users get no confirmation their
   input registered.

## Not applicable / verified clean

Recorded so these aren't re-audited later.

- **RTL** — no Arabic content anywhere (`lang="en"`, `dir="ltr"`, zero
  Arabic-range characters in rendered text). Not applicable until localisation is
  added.
- **Loading states** — N/A. Fully synchronous localStorage app, no network calls.
- **No-permission states** — N/A. No auth layer.
- **Empty states** — **genuinely well covered.** Every data view has an explicit
  message: portfolio overview (`index.html:1542`), gaps (`8808`), roadmap
  (`8895`, `8941`, `8943`, `8944`, `8946`), priorities (`8705`), report (`9521`),
  tables (`9169`). This is a strength, not a gap.
- **Form labels** — all 80+ controls are wrapped in `<label>`; zero missing labels.
- **Keyboard answering** — radios are real, focusable, `:focus-visible` works,
  labels are 484×88.
- **Focus rings** — present via UA default `outline:auto`; not suppressed.
- **Viewport meta** — correct, no `user-scalable=no`.
- **Horizontal overflow** — clean at 1440, 768 and 390. Only F3's band is broken.

### Two false leads, investigated and discarded

Noted because they look alarming if re-measured naively:

- White sidebar text initially measured at **1.08:1**. The first pass walked past
  the sidebar's `linear-gradient` (which sets no `background-color`) up to the page
  background. Re-run with gradient stop extraction: sidebar text passes
  comfortably. **Not a finding.**
- Answer radios initially looked unfocusable — the probe ran on the Dashboard view,
  where they are hidden. In the Assessment view they are real 17×17 focusable
  radios with a 484×88 label and working `:focus-visible`. **Keyboard answering is
  fine.**

## Deferred — needs your decision

**1. Card heading level (F6).** Cards are `<h2>` inside `<button>`.
- *Option A* — `<h3>` + `aria-label` on the button, keeping the visual design.
- *Option B* — drop the heading entirely and rely on the button's accessible name.

**2. Tablet density (F9).** At 768px you get one 705px card per row and nothing
above the fold.
- *Option A* — hold 2 columns down to ~600px.
- *Option B* — keep 1 column but collapse the sidebar to a compact horizontal
  strip on tablet.

**3. `alert()` replacement (F15).**
- *Option A* — minimal: add the F5 live region and route only errors through it
  (~20 min).
- *Option B* — full toast component for all six call sites (a small feature).
